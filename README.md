# Jarvis — голосовой помощник для Windows (C#/.NET 10, распознавание и голос офлайн)

Переписана идея из ролика «как сделать JARVIS на Python»: тот же набор команд,
но на C# вместо Python — быстрый старт, нет зависимостей от интерпретатора и pip,
один запускаемый exe.

## Запуск

```
Jarvis.exe                      помощник в панели: вкладки «ПУЛЬТ», «НАСТРОЙКИ» и «СЦЕНАРИИ», свернулся в трей
Jarvis.exe --console            то же самое без окна — чёрная консоль и голос, как раньше
Jarvis.exe --say "текст"        произнести текст
Jarvis.exe --listen 6           одно распознавание с микрофона (+ выполнение команды)
Jarvis.exe --plan               сухой прогон маршрутизации команд, без действий и звука
Jarvis.exe --selftest           проверка модели, голоса и цепочки TTS→STT без микрофона
Jarvis.exe --mics               список микрофонов, их уровни и основной в Windows
Jarvis.exe --mic 2              закрепить микрофон в настройках (--mic auto — снова искать самому)
Jarvis.exe --apps               список программ, которые помощник находит по имени
Jarvis.exe --apps "стим"        проверить, что откроется по этому слову (ничего не запускает)
Jarvis.exe --weather "Казань"   ответ сервиса погоды (тот же код, что и за голосовой командой)
Jarvis.exe --course "доллар"    курсы Центробанка
Jarvis.exe --translate "привет" перевод
Jarvis.exe --screen [файл.png] перевод активного окна (или файла) с впиской результата в кадр
Jarvis.exe --screen yandex    снимок экрана и авто-вставка в раздел «перевод по фото» Яндекса
Jarvis.exe --ocr файл.png [перевод.png]
                                только распознавание строк экрана, без захвата рабочего стола
Jarvis.exe --calc "12 на 3"     калькулятор, числа можно словами
Jarvis.exe --scenario           список сценариев из jarvis.json
Jarvis.exe --brain              проверка локальной нейросети: отвечает ли Ollama и есть ли модель
Jarvis.exe --brain "вопрос"     тот же вопрос, что помощник задаёт при непонятной фразе
Jarvis.exe --ui                 только панель настроек и управления, без распознавания
Jarvis.exe --render файл.png [--settings|--scenarios]
                                нарисовать панель офлайн и сохранить PNG (проверка дизайна без микрофона и без окон на экране)
Jarvis.exe --record 5 [номер]   записать микрофон в WAV, показать уровень и распознать
Jarvis.exe --wav "текст" [файл.wav] [усиление]   озвучить текст в файл
Jarvis.exe --voices             список голосов (нейросетевые + выбранный)
Jarvis.exe --voices demo        записать пример каждого голоса в папку диктовки
Jarvis.exe --windows            список открытых окон
Jarvis.exe --volume 40|mute|unmute
Jarvis.exe --transcribe file.wav
```

Структура папки: `Jarvis.exe` + `native/` (libvosk) + рядом `onnxruntime.dll`,
`sherpa-onnx-c-api.dll`, `piper_phonemize_core.dll` + `models/` (распознавание и голоса) +
`jarvis.json` (создаётся при первом запуске). Всё нужно держать вместе.

## Команды

открой/запусти X · открой сайт X · закрой X · закрой все окна · сверни X · разверни X · что открыто ·
найди X · следующий/предыдущий трек · пауза · стоп музыка · продолжи · полный экран ·
перемотай вперёд/назад · тише/громче · громкость 40 ·
звук отключи/включи · замолчи · диктуй → сохраняю/отменяю · который час · какое сегодня число ·
погода [в городе] · курс доллара (евро, юаня…) · переведи X на английский ·
перевод экрана · посчитай двенадцать на три · сценарий утро ·
повтори · режим ожидания · выход

Всё, что не похоже ни на одну из этих команд, уходит локальной нейросети — если она
установлена (см. «Умные ответы»).

## Погода, валюты, перевод и счёт

Четыре вещи, которые офлайн не сделать, идут в открытые API без ключей и регистрации
(`src/Net.cs` — общий клиент, 12 с на ответ):

* **погода** — `wttr.in` (`src/Weather.cs`). Город можно назвать в падеже («погода в казани»):
  склонённые названия приводятся к именительному, а если города в словаре нет, запрос уходит
  как есть. Город по умолчанию — `weatherCity` из `jarvis.json`.
* **курсы валют** — страница Центробанка (`src/Money.cs`), отвечает рубли за одну единицу и
  изменение за сутки; без названия валюты — сводка по доллару, евро и юаню.
* **перевод** — MyMemory (`src/Translate.cs`). Направление берётся из фразы («на немецкий»),
  без него — из алфавита самого текста.
* **калькулятор** — полностью офлайн (`src/Calc.cs`): распознаватель приносит числа словами,
  поэтому «сто двадцать на три», «15 процентов от 240», «корень из 144» считаются как есть.

Без интернета помощник говорит, что сервис не ответил, а не «не понял команду».
Проверить каждый ответ, не включая микрофон: `--weather`, `--course`, `--translate`, `--calc`.

## Перевод экрана

«Джарвис, перевод экрана» — это действие, приехавшее из проекта
[GRussianHotkey](https://github.com/morozkinvitalij12-lang/GRussianHotkey), где его запускала
комбинация клавиш. Здесь тот же путь стоит за голосовой командой (`src/ScreenTranslate.cs`):

1. снимается активное окно (если его нет — весь рабочий стол); кадр сразу уменьшается до
   размера, который берёт распознаватель;
2. текст распознаётся встроенным в Windows OCR (`Windows.Media.Ocr`) — это офлайн, ничего
   не скачивается и никуда не уходит; сначала английская модель, вторым проходом русская,
   строки в кириллице заменяют прочитанное англичанами;
3. направление задаётся каждой строке по её же алфавиту: латиница переводится на русский,
   кириллица — на английский. На странице, где русская статья соседствует с англоязычной
   аннотацией, один язык на весь экран оставлял половину текста нетронутой;
4. строки переводятся пачкой через открытый `translate.googleapis.com` (до 30 строк,
   HTTP/2 одним соединением — по одному соединению сервис отвечает `429`);
5. перевод вписывается прямо в кадр — цвет под строкой берётся из её же среднего цвета, а
   кегль подбирается так, чтобы строка влезла в своё место.

Показывает результат панель: окно поверх всего, закрывается по Esc, кликом, через минуту или
следующим переводом. В консольном режиме (`--console`) показывать нечего, и помощник зачитывает
перевод вслух.

### Яндекс Переводчик вместо своего распознавателя

В строке «ПЕРЕВОДЧИК ЭКРАНА» на вкладке «НАСТРОЙКИ» выбирается способ: `локальный` (путь выше)
или `Яндекс`. Во втором случае снимок активного окна кладётся в буфер обмена списком файлов,
открывается `translate.yandex.ru/ocr` — раздел «перевод по фото», — и помощник сам вставляет кадр
туда: распознаёт и переводит уже Яндекс, качество выше на мелком тексте и нерусских алфавитах.
Главная страница Переводчика картинку из буфера не принимает, кадр нужен именно в этом разделе.
Кадр пишется JPEG: полноэкранный PNG весит 4–5 МБ, а у страницы потолок 5 МБ, и тяжёлый файл она
молча отбрасывает. Вставка осторожная: `Ctrl+V` уходит только той вкладке, чей заголовок похож на
страницу переводчика, и только когда она удерживает передний план полторы секунды подряд (до 10
секунд на ожидание). Не дождались — клавиш нет никаких, а кадр остаётся в буфере обмена, и вставить
его нужно самому. `Ctrl+V` — единственные клавиши, которые помощник умеет отправлять; мышью он не
двигает и клики не шлёт никуда.

```
Jarvis.exe --screen yandex                 снять экран, положить в буфер и открыть Яндекс
```

Нужны пакеты распознавания текста: `--ocr снимок.png` печатает список установленных языков
(на машине это `en-US, ru`) и строки, которые OCR видит на картинке. Со вторым адресом тот же
запуск переводит и сохраняет кадр — проверка всего пути без захвата экрана:

```
Jarvis.exe --ocr снимок.png                что читает распознаватель
Jarvis.exe --ocr снимок.png перевод.png    полный путь команды по картинке
Jarvis.exe --screen [перевод.png]          то же, но по настоящему экрану
```

## Сценарии

Сценарий — цепочка обычных команд: «сценарий утро» говорит время, погоду, курсы и открывает
браузер. Шаги разбираются тем же кодом, что и голос, поэтому сценарий не умеет ничего, чего
нельзя добиться вслух.

```json
"scenarios": [
  { "name": "утро", "steps": ["который час", "погода", "курсы валют", "открой браузер"] }
]
```

Свои сценарии заводятся на вкладке «СЦЕНАРИИ»: `+ НОВЫЙ` открывает форму, в верхнее поле —
название (по нему сценарий зовётся вслух), в нижнее — команды, по одной на строку. `Ctrl+Enter`
или `СОХРАНИТЬ` записывает набор в `jarvis.json`, `Esc` закрывает правку, не трогая список.
`✎ ПРАВИТЬ` и `✕ УДАЛИТЬ` работают со строкой, выбранной в списке, а имя уже существующего
сценария не плодит дубликат — открывается его правка. Тот же файл правится и текстом, без
пересборки; список — `Jarvis.exe --scenario`. Запуск — щелчком по строке, Enter по выделенной
или голосом, а без голосовой сессии панель подскажет, что сказать вслух. Ответы шагов собираются
в одну реплику, чтобы помощник не заговорил четыре раза подряд.

## Плеер и видео

`следующий трек`, `пауза`, `стоп музыка` — это `WM_APPCOMMAND`, которые слышат Spotify, VLC,
Яндекс.Музыка и браузеры. `полный экран` и `перемотай` — одиночные клавиши (`F`/`Esc`,
`←`/`→`), отправленные активному окну через `PostMessage`: физическая мышь и клавиатура
не трогаются, поэтому помощник разворачивает видео, даже если вы держите мышь в игре.

Речь распознаётся офлайн двумя каналами: нейросетевой моделью GigaAM v3 (`sherpa-onnx`,
225 МБ, см. ниже) и словарным Vosk (`vosk-model-small-ru-0.22`). Словарный Vosk собирает фразу
только из слов команд (`src/Vocabulary.cs`), поэтому посторонняя речь не превращается в
случайные команды, а свободный Vosk отвечает за аргументы («найди погоду в Москве»), диктовку
и имя помощника — GigaAM не потоковый и имя по времени не ищет. Как только фраза закончилась,
помощник прогоняет её целиком через GigaAM и сравнивает число командных слов в расшифровках
(`Vocabulary.Score`): берётся та, где команда слышна полнее. Так «открой браузер» перестаёт
быть «браузером», а «какая погода в Казани» — «погодой в казарме». Если словарный вариант не
похож ни на одну команду, помощник пробует свободную расшифровку и только потом спрашивает
нейросеть (или говорит «не понял»). Ответы озвучивает
нейросетевой голос Piper (`sherpa-onnx`, тот же процесс, без интернета): он заметно живее,
чем системный SAPI. Типовые реплики озвучиваются заранее и остаются в памяти, поэтому
первый ответ звучит без задержки. Если папки с голосами нет, помощник сам откатывается
на SAPI и говорит тем, что есть в Windows.

## Распознавание речи (GigaAM)

GigaAM v3 — русская модель Сбера, открытая и бесплатная; в помощник она упакована в int8 и
живёт в том же процессе, что и голоса (тот же `sherpa-onnx-c-api.dll`, отдельной программы не
нужно). Скачивать её не обязательно: без папки с модельюпомощник работает как раньше, только Vosk.

```
models\sherpa-nemo-giga-am-v3\model.int8.onnx     225 МБ
models\sherpa-nemo-giga-am-v3\tokens.txt          34 строки
```

Скачать можно одним запросом (из папки помощника):

```
curl -L -o models/sherpa-nemo-giga-am-v3/model.int8.onnx https://huggingface.co/csukuangfj/sherpa-onnx-nemo-ctc-giga-am-v3-russian-2025-12-16/resolve/main/model.int8.onnx
curl -L -o models/sherpa-nemo-giga-am-v3/tokens.txt https://huggingface.co/csukuangfj/sherpa-onnx-nemo-ctc-giga-am-v3-russian-2025-12-16/resolve/main/tokens.txt
```

Стоит модель около гигабайта памяти и поднимается секунду; фраза в три секунды декодируется
за 150 мс, поэтомупомощник не «тупит» после команды. Отключить — строка «Слух» в НАСТРОЙКАХ или
`neuralAsr: false` в `jarvis.json` (например, если память нужнее в игре). Проверить, что
модель поднялась и насколько она слышит лучше словарь, — `Jarvis.exe --selftest`: там две
строки итога, `Vosk …` и `GigaAM …`.

## Умные ответы (Ollama + Qwen)

Непонятная фраза — не тупик: помощник спрашивает локальную нейросеть и озвучивает её ответ
тем же голосом. Работает полностью офлайн и бесплатно: `Ollama` крутит модель на вашем же
компьютере, никаких ключей и облаков (`src/Brain.cs`, запрос к `http://127.0.0.1:11434/api/chat`).

Установка один раз:

```
winget install Ollama.Ollama        или скачайте OllamaSetup.exe с ollama.com/download
ollama pull qwen3.5:4b              ~3,3 ГБ, модель ляжет в C:\Users\<вы>\.ollama
Jarvis.exe --brain                  «Ollama отвечает… Нужная «qwen3.5:4b» на месте»
Jarvis.exe --brain "почему небо голубое"   проверка самого ответа
```

Нужны 64-битная Windows и ~8 ГБ свободной памяти. На видеокарте ответ приходит за 1–5 с,
на процессоре — за 5–30 с, поэтому перед ответом помощник говорит «Секунду, уточняю».
Ждём не дольше `brainTimeoutSeconds`.

Что мешает работе — честно проговаривается, а не роняет сессию:

| случай | помощник скажет |
|---|---|
| Ollama не запущена | «Не слышу свою нейросеть: похоже, Ollama не запущена.» |
| модели нет | «Модель нейросети не загружена — команду установки записал в журнал.» |
| думала слишком долго | «Нейросеть не успела ответить. Попробуйте ещё раз чуть позже.» |
| ответ пустой или непонятный | «Нейросеть ответила невразумительно.» |

После «сервиса нет» помощник не дёргает нейросеть на каждую фразу две минуты (после
таймаута — 30 секунд) и об этом молчит: обычные команды работают как раньше. Ответ
модели чистится от markdown, списков и переносов и обрезается до ~420 знаков, чтобы
его было приятно слушать. Выключить функцию — строка «Умные ответы» в НАСТРОЙКАХ
или `smartAnswers: false` в `jarvis.json`.

Меняется модель одной строкой — `ollamaModel` в `jarvis.json` плюс `ollama pull <имя>`; каталог
моделей — https://ollama.com/library . «Думающие» модели (линейка Qwen 3) тратят весь лимит
токенов на скрытое рассуждение и присылают пустой ответ, поэтому помощник всегда шлёт
`think: false`.

## Голос

```
Jarvis.exe --voices            что установлено и что выбрано
Jarvis.exe --voices demo       в Documents\Jarvis появятся файлы голос-*.wav — послушайте и выберите
```

Выбор — одной строкой в `jarvis.json`: `"piperVoice": "denis"` (варианты: `denis`, `dmitri`,
`ruslan`, `irina`). `piperSpeed` — темп речи (1.0 = нормально, 0.9 = медленнее).

Сверху на голос ложится обработка `voiceFx` — она делает из «человека, читающего текст» бортовой
ИИ: тон ниже на 1,8 полутона, фраза примерно на 11 % длиннее, из тембра вырезан гул ниже 60 Гц и
«грудной» диапазон 300–700 Гц, добавлен подъём на 2–5 кГц, короткий комнатный хвост и едва
слышимый двойник с плывущей задержкой. Громкость реплик при этом остаётся прежней, так что
ползунок громкости ведёт себя как раньше. Это обычные фильтры над свободной моделью голоса:
записей актёра из фильма в проекте нет, и скопировать чужой голос они не пытаются.

`"voiceFx": "jarvis"` (по умолчанию) или `"off"` — то же самое переключается строкой «Тембр» на
вкладке «Настройки» и применяется после перезапуска. На системный голос (`"tts": "sapi"`)
обработка не действует. Разборчивость не страдает: `--selftest` с эффектом и без даёт одинаковые
29/29 фраз.

## Настройка (`jarvis.json`)

| поле | смысл |
|---|---|
| `wakeWords` | слова активации, допускается опечатка распознавателя |
| `tts` | `piper` (нейросетевой) или `sapi` (системный) |
| `piperVoice` | какой из установленный голосов брать (`denis`, `irina`, …) |
| `piperSpeed` / `piperThreads` | темп речи и число потоков на синтез |
| `voiceFx` | обработка голоса под бортовой ИИ: `jarvis` или `off` (см. «Голос») |
| `microphone` | индекс микрофона (`--mic 2`), `-1` = автопоиск живого |
| `overlay` | показывать окно панели при запуске; `false` — старт сразу в трей (Ctrl+Alt+Space вызывает его в любом случае) |
| `modelDir` | путь к модели Vosk |
| `neuralAsr` | слушать ли фразы нейросетевой моделью GigaAM (`false` — только Vosk) |
| `neuralAsrDir` / `neuralAsrThreads` | путь к `model.int8.onnx` и число потоков на декод |
| `voiceCulture` / `speechRate` / `volume` | параметры системного голоса и громкость реплик |
| `commandTimeoutSeconds` | сколько ждать команду после активации; пока вы говорите, окно ожидания продлевается |
| `partialTimeoutSeconds` | сколько тишины считать концом фразы |
| `dictationDir` | куда сохранять диктовку |
| `weatherCity` | город по умолчанию для «погода» |
| `scenarios` | сценарии: имя и цепочка обычных команд (см. «Сценарии») |
| `sites` | свои сайты: имя → адрес (см. «Сайты») |
| `smartAnswers` | озвучивать ли ответ локальной нейросети на непонятные фразы |
| `ollamaUrl` / `ollamaModel` | адрес Ollama и модель (`qwen3.5:4b`) |
| `brainTimeoutSeconds` | сколько секунд ждать ответ нейросети (на процессоре модель долго грузится) |

## Панель, трей и клавиши

Одно окно в стиле HUD: слева круговой «пульс» (кольцо делений, янтарная и голубая дуги,
статус — `ожидание` / `команда` / `пауза`), справа три вкладки.

* **ПУЛЬТ** — живой журнал помощника (то, что раньше печаталось в консоль) и строка ввода:
  команду можно набрать текстом вместо голоса.
* **НАСТРОЙКИ** — строки-настройки (микрофон, голос, движок речи, громкость, заглушка,
  пауза, умные ответы, окно при запуске) переключаются Enter или кликом и сразу пишутся в `jarvis.json`;
  громкость и заглушка применяются сразу, микрофон и голос — после перезапуска помощника.
  Строки-действия: проверить микрофон, проверить нейросеть, самопроверка, примеры голосов.
  Поиск фильтрует строки.
* **СЦЕНАРИИ** — цепочки команд из `jarvis.json`; щелчок или Enter запускают сценарий,
  под именем видны сами шаги.

Клавиши: **F6** — выключить/включить помощника (он молчит и не слушает, но остаётся в трее),
**Ctrl+Alt+Space** — показать/скрыть окно, **Esc** — спрятать окно, стрелки и Enter — навигация
по строкам активной вкладки (настройки, сценарии). Крестик не закрывает помощника, а прячет его в трей; настоящий выход — через
меню значка («Выйти») или голосовую команду «выход». Значок в трее: голубой — слушает,
янтарный — выключен; правый клик — открыть / выключить (F6) / выйти.

F6 перехватывается на уровне системы, поэтому в браузере она перестанет обновлять страницу,
а в играх пропадёт привязка этой клавиши. Если это мешает, замените в `src/Shell.cs`
`RegisterHotKey(..., PauseHotkey, ModNoRepeat, VkF6)` на `0x0003` (Ctrl+Alt) + `VkF6`.

`overlay` в `jarvis.json` — показывать ли окно сразу после запуска; `false` значит старт
сразу в трей.

## Какие программы находятся по голосу

`открой X` и `закрой X` ищут X в трёх слоях: словарь алиасов (`src/Commands.cs`), индекс
установленного — ярлыки меню «Пуск» и реестр App Paths (`src/AppsIndex.cs`) — и, если ничего
не подошло, запуск как команды Windows. Индекс сравнивает имена в латинице и по скелету
согласных, поэтому «стим», «стима» и steam ведут в один и тот же `steam.exe`, а «тлаунчер» —
в TLauncher. Проверить без запуска: `Jarvis.exe --apps стим`; полный список — `Jarvis.exe --apps`.
Если программа не находится, ярлык должен лежать в меню «Пуск» (тогда достаточно добавить
его туда) — или допишите алиас в словарь и пересоберите.

## Сайты

`открой ютуб`, `открой сайт авито`, `открой сайт википедия` — адрес берётся из таблицы
`src/Sites.cs` (имена вроде youtube/ютуб, vk/вконтакте, ок, авито, дзен, rutube, habr, pikabu,
reddit, twitch, discord, telegram, steam, epic, netflix, kinoepoisk, ozon, wildberries,
aliexpress, gosuslugi, github, stackoverflow, переводчик, почта, маркет и другие) и открывается
в брауфере по умолчанию через `ShellExecute`. Слово «сайт» в фразе меняет порядок: с ним помощник
ищет только среди сайтов, без него — сначала программы, поэтому «открой стим» запустит
`steam.exe`, а «открой сайт стим» поведёт на steampowered.com. Адрес, сказанный словами
(`ют ю туб точка ком`, `github.com`), распознаётся как адрес и открывается как есть.

Свои имена дописываются в `jarvis.json` и перекрывают встроенные — пересобирать ничего не
нужно, но файл помощник читает один раз при старте, поэтому после правки его надо перезапустить:

```json
"sites": { "косматая": "kosmataya.ru", "работа": "https://jira.example.com" }
```

Совпадение терпимое к тому, что делает распознаватель: «ю туб» склеивается в «ютуб», короткое
имя (`ок`) ловится только целым словом, длинное (от 4 букв) — и внутри слова. Проверить:
`Jarvis.exe --sites` печатает все имена с адресами, `Jarvis.exe --plan "открой сайт косматая"`
показывает, что помощник собирается сделать, ничего не открывая.

## Безопасный режим

`JARVIS_DRY=1` — команды разбираются и печатаются, но ничего не закрывается, не запускается
и не произносится. На этом режиме построена самопроверка.

`JARVIS_FREE=1` — `--transcribe` и `--listen` работают свободной моделью без словаря: удобно
сравнить, что распознаётся лучше, если команда ведёт себя странно.

## Если помощник молчит или закрылся

При старте Jarvis слушает каждый микрофон ~0,4 с и берёт тот, где есть сигнал: основной
микрофон Windows иногда отдаёт цифровой ноль (USB-адаптер без капсулы, выключенная кнопка).
Если помощник не слышит команд, запустите `Jarvis.exe --record 5` и скажите что-нибудь:
строка «пик» должна быть в тысячах. Почти нулевой пик — проблема в устройстве или в его
уровне записи (Параметры → Система → Звук → Свойства микрофона), а не в распознавании.
Закрепить нужное устройство навсегда: `Jarvis.exe --mic 2` (вернуть автопоиск: `--mic auto`).

`--selftest` проверяет модель, голос и стресс-фазу (четыре потока озвучки одновременно плюс
непрерывный сброс распознавателя). Необработанные ошибки фоновых потоков пишутся одной строкой
в `jarvis-crash.log` рядом с `Jarvis.exe`.

## Сборка

```
dotnet publish -c Release -r win-x64 --self-contained true -o dist
```

Нужен .NET SDK 10. Целевой фреймворк — `net10.0-windows10.0.19041.0`: версия Windows нужна,
чтобы был доступ к WinRT-распознаванию текста (`Windows.Media.Ocr`), то есть помощник требует
Windows 10 19041 и новее. Нативные `libvosk*.dll` лежат в `native/` (берутся из NuGet-пакета Vosk),
модель — в `models/`. Запуск — одним `Jarvis.exe`, остальные файлы должны лежать рядом.

`-p:PublishSingleFile=true` не используем: Smart App Control в Windows 11 молча запрещает
запуск неподписанного однофайлового exe («Отказано в доступе», в журнале
`Microsoft-Windows-CodeIntegrity/Operational` — события 3033/3077), а WPF-нативные dll внутри
такого файла раньше давали `DllNotFoundException`. Сборка папкой запускается и там, и там.

## Отличия от Python-версии из ролика

* старт и загрузка модели ~0,5 с вместо запуска интерпретатора и десятков pip-зависимостей;
* распознавание и окна работают в одном процессе без `subprocess` и `pyttsx3`;
* закрытие окон — `EnumWindows` + `DWMWA_CLOAKED` + `WM_CLOSE` через `SendMessageTimeout`
  (не зависает на подвешенных окнах), свои окна и тул-окна пропускаются;
* громкость через Core Audio (точное значение), а не клавиши-эмуляции;
* самопроверка без микрофона: TTS пишет WAV → Vosk читает → сравнивается текст.
